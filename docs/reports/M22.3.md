# M22.3 Report — Unlock and Implement Multi-Instance (Đa phiên)

## Summary
Unlocked the Multi-Instance (`Đa phiên`) UI in `SettingsPage.xaml`, removed the hardcoded unavailable warning banner, wired the checkbox directly to `SettingsViewModel.MultiInstanceToggledCommand` and persistent `AppSettings`, and ensured `NamedMutexInstanceGate` creates and holds the `ROBLOX_singletonEvent` mutex in the background alongside sequential multi-account launches.

## Key Changes
1. **Unlock Settings UI (`src/App.Wpf/Views/Pages/SettingsPage.xaml`)**:
   - Enabled `Settings_MultiInstanceToggle` (`CheckBox`) and wired `Command="{Binding MultiInstanceToggledCommand}" CommandParameter="{Binding RelativeSource={RelativeSource Self}, Path=IsChecked}"`.
   - Removed the hardcoded orange warning banner (`Strings.MultiInstanceNotAvailable`).
2. **Settings Persistence & Live Mutex Activation (`src/App.Wpf/ViewModels/SettingsViewModel.cs`, `src/Core/Settings/AppSettings.cs`)**:
   - Added `AppSettings.IsMultiInstanceEnabled` alias and updated `SettingsViewModel` so toggling the Multi-Instance checkbox or saving settings immediately calls `_instanceGate.TryEnable()` / `_instanceGate.Disable()` and persists `MultiInstanceEnabled` to `settings.json`.
3. **Background `ROBLOX_singletonEvent` Mutex & Sequential Launch Integration (`src/Infrastructure/Instance/NamedMutexInstanceGate.cs`, `src/App.Wpf/ViewModels/AccountsViewModel.cs`)**:
   - Holds `ROBLOX_singletonEvent` and `ROBLOX_singletonMutex` on the dedicated background worker thread `RbxManager_InstanceGateWorker` and automatically ensures the gate is active before running `ExecuteSequentialLaunchQueueAsync`.
