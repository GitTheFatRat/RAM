# M21.7 Report — Native Sign-Up Form & Automatic Cookie Extraction via CDP

## 1. Root Cause & Diagnostics
- **Why `/NewLogin?returnUrl=%2FCreateAccount` only rendered Login**:
  - `ReactLogin.js` on `/NewLogin` mounts the Login UI (`#react-login-web-app`) and hides the Sign-Up link whenever `apis.roblox.com/universal-app-configuration/v1/behaviors/intl-auth-compliance/content` returns `isVNGComplianceEnabled: true` (which occurs for all Vietnam IPs, including Cloudflare WARP Vietnam egress IPs).
  - Meanwhile, Roblox's root `/` and `/login` routes are tarpitted (`HTTP 000`) by Roblox's Envoy edge gateway (`public-gateway`) for `loc=VN` IPs.
- **Option A Live Diagnostic Result (`https://auth.roblox.com/v2/signup` & `Challenge.js`)**:
  - Live diagnostic against `https://auth.roblox.com/v1/usernames/validate`, `https://auth.roblox.com/v2/passwords/validate`, `https://apis.roblox.com/user-agreements/v1/agreements-resolution/web`, and `https://auth.roblox.com/v2/signup` confirmed that all registration API endpoints are **100% unblocked (`HTTP 200 OK`)** from Vietnam IPs.
  - Calling `POST https://auth.roblox.com/v2/signup` directly returns `403 Forbidden` with `rblx-challenge-type: captchav2` (Arkose FunCaptcha).
  - Crucially, `https://www.roblox.com/NewLogin` (`HTTP 200 OK` in `~0.5s`) already loads `window.CoreUtilities.httpService` and `window.Roblox.AccountIntegrityChallengeService.Generic.intercept` (`Challenge.js`). When `window.CoreUtilities.httpService.post({ url: 'https://auth.roblox.com/v2/signup', withCredentials: true }, payload)` is invoked inside `/NewLogin`, `Challenge.js` automatically intercepts the `403` challenge response, mounts the official Arkose FunCaptcha modal (`#modal-dialog` / `arkose-...-wrapper`) on `document.body`, and resubmits the signup request once the CAPTCHA is solved.

## 2. Solution Implemented
- **CDP Sign-Up UI Injection (`IncognitoBrowserLauncher.cs`)**:
  - Updated [`IncognitoBrowserLauncher.SignUpUrl`](../../src/App.Wpf/Services/IncognitoBrowserLauncher.cs) to `"https://www.roblox.com/NewLogin#signup"`.
  - When `IncognitoBrowserLauncher.TryLaunch` starts a Chromium browser, it allocates an isolated temporary `--user-data-dir` and local `--remote-debugging-port` alongside `--incognito --disable-quic --disable-features=EncryptedClientHello,Kyber,PostQuantumCECPQ2`.
  - For `#signup`, the background CDP WebSocket session injects `SignUpDomScript` via `Page.addScriptToEvaluateOnNewDocument` and `Runtime.evaluate`, hiding `#react-login-web-app` and mounting the native dark-themed **Đăng ký Roblox (Create Account)** form (`#rbx-mgr-signup-root`) with:
    - Birthday selectors (Day / Month / Year)
    - Live Username validation (`GET https://auth.roblox.com/v1/usernames/validate`)
    - Live Password validation (`POST https://auth.roblox.com/v2/passwords/validate`)
    - Gender selection (Female / Male)
    - Direct registration via `window.CoreUtilities.httpService.post({ url: 'https://auth.roblox.com/v2/signup', withCredentials: true }, ...)` with automatic official Arkose CAPTCHA modal handling.
- **Automatic `.ROBLOSECURITY` Cookie Extraction**:
  - The CDP session polls `Network.getAllCookies` for `.ROBLOSECURITY` (`HttpOnly`). As soon as the user finishes signing up or logging in, the cookie is displayed in a copyable banner inside the browser AND automatically appended to `AddAccountViewModel.RawCookiesText` via `IncognitoBrowserLauncher.CookieCaptured`.

## 3. CSP & Anti-Bot Hardening (`Press and hold` / PerimeterX Challenge)
- **Root Cause of `error1.png` / `error2.png` (`Press and hold — Please try again`)**:
  - On `/NewLogin`, Roblox's `Content-Security-Policy` header omits `blob:` from `script-src` / `worker-src`. When the PerimeterX (`px-cdn.net` / `CaptchaV2`) "Press and hold" human verification modal spawned `blob:` Web Workers (`new Worker('blob:...')`), Chrome blocked all 76 worker creation attempts due to CSP.
- **Fix**:
  - Updated [`IncognitoBrowserLauncher`](../../src/App.Wpf/Services/IncognitoBrowserLauncher.cs) to launch the browser on `about:blank` with `--disable-blink-features=AutomationControlled`, immediately enable `Page.setBypassCSP({ enabled: true })` and `Page.addScriptToEvaluateOnNewDocument` (without enabling `Runtime.enable` or polling `Runtime.evaluate` during user interaction), and then navigate to `https://www.roblox.com/NewLogin#signup`.
  - Both top-frame and child-iframe `blob:` Web Workers now execute with 0 CSP violations.

## 4. Verification
- `dotnet test -c Release`: All 300 unit and integration tests pass with 0 warnings and 0 errors.
- Live headless Chrome CDP verification confirmed `#rbx-mgr-signup-root` auto-mounts, `navigator.webdriver` is `undefined`, and `blob:` Web Workers execute with 0 CSP errors.
