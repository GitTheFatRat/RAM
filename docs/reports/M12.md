# M12 Report: Smart Auto-Rejoin (Server Hopping on Crash)

**Target**: Post-v0.3.0 Feature  
**Date**: 2026-10-22  
**Status**: All Gates Passed

---

## 1. Scope & Implementation Summary

### Core
- **Settings**:
  - `AppSettings` gains: `bool EnableSmartServerHopping` (default: `true`).
  - Clamping logic preserves valid configuration.

### Infrastructure
- **`SessionTracker`**:
  - Injected `IServerBrowserService` and `ISettingsService`.
  - When handling an auto-rejoin for an unexpectedly closed session:
    - Verifies `AppSettings.EnableSmartServerHopping`.
    - If enabled: queries `IServerBrowserService.GetServersAsync(session.Request.PlaceId, ServerSort.Ascending, null, CancellationToken.None)`.
    - Filters available public servers: selects the first server that is not full (`Playing < MaxPlayers`) and has a non-empty `Id`.
    - Clones the original `LaunchRequest` with the newly selected server's `JobId`.
    - Failure fallback: if `GetServersAsync` fails, times out, or returns no available servers, catches exceptions safely and gracefully falls back to rejoining using the original `LaunchRequest`.
    - Logs server hop selection and fallback counts.

### App.Wpf
- **Settings View & ViewModel**:
  - Added `EnableSmartServerHopping` observable property to `SettingsViewModel`.
  - Added `ui:ToggleSwitch` for "Enable Smart Server Hopping on Rejoin" in `SettingsPage.xaml` under the Auto-rejoin card.
  - Localization parity added to `Strings.resx` and `Strings.vi.resx`:
    - `EnableSmartServerHopping`
    - `EnableSmartServerHoppingDescription`
