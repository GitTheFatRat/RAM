# Milestone Report - M28.7: Window Size Lock (Replaces the Denied FastFlags)

## Root Cause
1. **FastFlags rejected.** The Roblox player log for 0.744.0.7441080 shows:
   `Warning [FLog::FlagFetchingStarterModule] Denied local configuration for: DFIntWindowSizeMinX / DFIntWindowSizeMinY`.
   These flags aren't on Roblox's client FFlag allowlist, so M28.6's approach can never work.
2. **M28.6 regression.** M28.6 dropped `SWP_NOSENDCHANGING`, so the initial resize was clamped by Roblox's
   `WM_GETMINMAXINFO` (`ptMinTrackSize = 800x600`). The log shows the swapchain never left `800x599`.
3. **Drag snap-back.** Windows' modal move/size loop re-applies `ptMinTrackSize` when a drag starts. Without
   code inside Roblox (DLL injection, which Hyperion bans) this can't be stopped, only corrected afterwards.

## Fix
- `User32.ResizeWindow` restores `SWP_NOMOVE | SWP_NOZORDER | SWP_NOACTIVATE | SWP_NOSENDCHANGING`.
  `ResizeProcessMainWindowAsync` now returns the `hWnd`.
- New `WindowSizeLock` (`src/Infrastructure/Native/WindowSizeLock.cs`) uses out-of-context `SetWinEventHook`,
  filtered to the Roblox PID. No code runs inside Roblox.
  - `EVENT_SYSTEM_MOVESIZEEND` restores the size after the user releases a drag.
  - `EVENT_OBJECT_LOCATIONCHANGE` (outside a drag) restores the size if Roblox resizes itself.
  - `EVENT_OBJECT_DESTROY` unhooks automatically.
  - Size only (`SWP_NOMOVE`), so position stays fully user-controlled. Minimized/maximized windows are left alone.
  - Burst guard: at most 8 corrections per second, so it can't ping-pong with the client.
- New `RobloxWindowSizer` (App.Wpf) resizes the window and attaches the lock on the UI dispatcher (WinEvent
  callbacks are pumped by the installing thread). Used by `AccountsViewModel` and `ServersViewModel`.
- Removed `RobloxFastFlagInjector` and its tests. Deleted the generated `ClientAppSettings.json`.

## Verification
- `dotnet test`: 310 passed, 0 warnings.
- **Live Roblox window** (`RobloxPlayerBeta.exe --app`, class `WINDOWSCLIENT`, build 0.744.0.7441080), using the shipped code:
  - Start: `816x638` (client `800x599`).
  - `ResizeWindow(300, 400)` returned `true` and the window became `300x400`. It held for 2.5 s.
  - Forced normal resize to 800x600 (the same clamp Roblox applies) gave `816x638`. The lock restored `300x400` within 700 ms.
  - Moved to (400,300): size stayed `300x400`. Still `300x400` after 3 s idle.
- Follow-up (`4729a6f`): the lock is now tracked per process. It adopts any new captioned top-level window the
  process shows (Roblox recreated its window during testing) and unhooks when the process exits.
- Note: the user's first "still 800x600" report came from a manager instance started at 22:19, before this build was published.
