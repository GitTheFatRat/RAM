## 1. Scope & Honest Limits

### Purpose & Limits
1. **Network Scope**: The configured proxy routes the login browser (WebView2) and all subsequent application-initiated HTTP requests (cookie validation, authentication ticket requests, server queries). The Roblox game client (`RobloxPlayerBeta.exe`) is launched directly by the Windows shell via the `roblox-player:` protocol and **does NOT** use this proxy.
2. **Honesty Regarding Platform Action**: This tool does not claim that proxies prevent bans, flags, or specific Roblox error codes.
3. **No Third-Party Calls**: No external IP-check, geolocation, or third-party web services are contacted; only official `roblox.com` and `*.roblox.com` endpoints are queried.

## 2. Implementation Details

1. **Pre-Login Panel (`LoginWindow`)**:
   - Designed a pre-login panel in [`LoginWindow.xaml`](file:///C:/Users/Administrator/Desktop/RAM%20CLONE/src/App.Wpf/Views/Windows/LoginWindow.xaml) displayed before any browser is instantiated.
   - Allows choosing proxy type (`None (Direct Connection)`, `HTTP`, `SOCKS5`), configuring Host, Port, Username, and Password (`PasswordBox`).
   - "Test proxy" builds a transient `HttpClient` via `RobloxHttpClientFactory.CreateHandler` (10s timeout, no cookies, no redirects) and tests reachability to `https://www.roblox.com/`. Does not display or log proxy credentials.
   - "Start browser" performs strict validation before dynamically creating the `WebView2` control in code.
2. **Strict Validation (`ProxyConfigValidator`)**:
   - Implemented `ProxyConfigValidator.ValidateStrict()` in `Core/Validation/ProxyConfigValidator.cs` to prevent command-line flag injection via `AdditionalBrowserArguments`.
   - Host validated against maximum 253 chars, letters/digits/dot/hyphen or valid IPv4/IPv6 literals. Rejects whitespace, control characters, quotes, slashes, colons outside IPv6, leading hyphens, and empty labels.
   - Port constrained to integer range 1 to 65535.
   - Username bounded to 128 characters, password bounded to 256 characters, no control characters.
3. **Browser Argument Builder (`ProxyBrowserArgumentBuilder`)**:
   - Pure function mapping HTTP to `--proxy-server=http://{host}:{port}`, SOCKS5 to `--proxy-server=socks5://{host}:{port}`, with IPv6 literals properly enclosed in brackets (e.g. `[2001:db8::1]`), and None returning null.
4. **Proxy Authentication (`WebViewProxyAuthHandler`)**:
   - Subscribes to `CoreWebView2.BasicAuthenticationRequested`.
   - Uses `ProxyAuthenticationDecision.ShouldAuthenticate` to verify the challenge URI host matches the configured proxy host (case-insensitive) and that credentials exist.
   - Cancels the authentication challenge for non-proxy hosts or when credentials are absent.
   - Transient `PasswordBox` content is converted to `SecretValue` immediately; `SecretValue.Reveal()` is invoked strictly inside `WebViewProxyAuthHandler` at the exact point of response assignment.
   - Added `src/App.Wpf/Services/WebViewProxyAuthHandler.cs` to `ArchitectureTests.AllowedRevealRelativePaths` (allowlist increased by exactly 1 entry).
5. **Account Persistence**:
   - [`AccountsViewModel.AddViaLoginAsync`](file:///C:/Users/Administrator/Desktop/RAM%20CLONE/src/App.Wpf/ViewModels/AccountsViewModel.cs) retrieves `loginWindow.UsedProxy` and stores it on the newly created `Account`, carrying it forward to immediate cookie validation.
