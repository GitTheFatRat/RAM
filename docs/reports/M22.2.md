# M22.2 Report — Fix Sequential Launch Only Executing or Retaining the Last Selected Account

## Root Cause Analysis
1. **Primary Launch Button Ignored Checked Accounts (`src/App.Wpf/ViewModels/AccountsViewModel.cs`)**:
   - When the user checked 3 accounts in the `DataGrid`, clicking the 3rd checkbox also set `SelectedAccount` (`SelectedItem`) to the 3rd (last) row. Clicking the primary **Launch (`Mở game`)** button invoked `LaunchAccountCommand`, which only launched `SelectedAccount` (the last account clicked) instead of the checked accounts (`IsSelected == true`).
   - Additionally, `LoadAccountsAsync()` recreated `AccountItemViewModel` instances without preserving `IsSelected`.
2. **`ROBLOX_singletonEvent` Kernel Object Type & Automatic Activation (`src/Infrastructure/Instance/NamedMutexInstanceGate.cs`, `src/App.Wpf/App.xaml.cs`)**:
   - `NamedMutexInstanceGate` previously created `ROBLOX_singletonEvent` as an `EventWaitHandle(initialState: true, EventResetMode.ManualReset)` instead of a `Mutex`. Because `RobloxPlayerBeta.exe` uses `CreateEventW(..., L"ROBLOX_singletonEvent")` to signal and terminate older Roblox instances when a new instance starts, creating it as a signaled Event allowed each subsequent Roblox launch to close the previous client, leaving only the last account open. Locking `ROBLOX_singletonEvent` as a `Mutex` causes `CreateEventW` in `RobloxPlayerBeta.exe` to fail with `ERROR_INVALID_HANDLE`, preventing new clients from terminating earlier ones.
   - `App.xaml.cs` and `ExecuteSequentialLaunchQueueAsync` now automatically enable `IInstanceGate.TryEnable()` at startup and before launching the queue.

## Key Changes
- **`src/App.Wpf/ViewModels/AccountsViewModel.cs`**:
  - Added `GetSelectedAccountsInQueueOrder()` and updated `LaunchAccountAsync()` and `LaunchSelectedAccountsAsync()` to pull all checked accounts (`IsSelected == true`) in top-to-bottom UI order and snapshot the queue before iterating.
  - Preserved `IsSelected` across `LoadAccountsAsync()` reloads and wired `PropertyChanged` notifications for `HasCheckedAccounts` and `CanLaunchAccount`.
  - Enabled `_instanceGate.TryEnable()` prior to sequential launch and added `"Queued X accounts for launch..."` UI status and console/Serilog logging.
- **`src/Infrastructure/Instance/NamedMutexInstanceGate.cs`**:
  - Locked `ROBLOX_singletonEvent` as a `Mutex` alongside `ROBLOX_singletonMutex`.
- **`src/App.Wpf/App.xaml.cs` & `src/App.Wpf/ViewModels/ServersViewModel.cs`**:
  - Automatically enabled `IInstanceGate` on startup and before multi-account server joins.
