# M26 Report — Robust Multi-Roblox Bypass (Permanent Global Mutex & Security Rules)

## Changes
1. **Permanent `Global\ROBLOX_singletonEvent` & `ROBLOX_singletonMutex` with Lenient Security (`src/Infrastructure/Instance/NamedMutexInstanceGate.cs`, `src/App.Wpf/App.xaml.cs`)**
   - Updated `NamedMutexInstanceGate.DefaultEventName` to `@"Global\ROBLOX_singletonEvent"`.
   - Added `private static Mutex? _globalRobloxMutex` and `private static Mutex? _globalRobloxSingletonMutex` in `App.xaml.cs` with `GC.KeepAlive(...)` so the handles remain rooted for the entire application lifetime.
   - Configured `MutexSecurity` with `WellKnownSidType.WorldSid` (`MutexRights.FullControl`, `AccessControlType.Allow`) on mutex creation so Roblox processes running across User/Admin integrity boundaries can open the object without access denied errors.
   - Gracefully attaches when the mutex is already created by an external utility (`createdNew == false`) in production mode without crashing.
2. **Background Maintenance & Handle Closer (`src/Infrastructure/Instance/RobloxHandleCloser.cs`)**
   - Added a 3-second maintenance loop on `RbxManager_InstanceGateWorker` while `IsMultiInstanceEnabled` is active that scans running `RobloxPlayerBeta.exe` processes via `NtQuerySystemInformation` / `DuplicateHandle` (`DUPLICATE_CLOSE_SOURCE`) and closes any `ROBLOX_singletonEvent` or `ROBLOX_singletonMutex` handles.
