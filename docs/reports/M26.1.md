# M26.1 Report — Clone "Multiple Roblox V2.2" Bypass Logic

## Analysis of `MultipleRobloxInstances-V2.2`
Inspection of `multi_roblox_example/MultipleRobloxInstances-V2.2/MultipleRobloxInstances.dll` & `.pdb` (`MainWindow.xaml.cs`) revealed the three-step mechanism used by V2.2:
1. **Pre-Close Existing Singleton Locks**:
   - Calls `Mutex.OpenExisting("ROBLOX_singletonMutex").Close()` and `Mutex.OpenExisting("ROBLOX_singletonEvent").Close()` before acquiring its own lock.
2. **Persistent Mutex Lock**:
   - Acquires and holds `new Mutex(true, "ROBLOX_singletonMutex", out success)` alongside `ROBLOX_singletonEvent` for the lifetime of the window.
3. **Error 773 Teleport/Multi-Client Cookie File Lock**:
   - Opens `%LocalAppData%\Roblox\LocalStorage\RobloxCookies.dat` with `new FileStream(..., FileMode.Open, FileAccess.Read, FileShare.None)` so concurrent `RobloxPlayerBeta.exe` instances cannot overwrite or lock each other out of `RobloxCookies.dat`.

## Implementation in RbxManager
1. **`NamedMutexInstanceGate` (`src/Infrastructure/Instance/NamedMutexInstanceGate.cs`)**:
   - Replicated V2.2's `TryCloseExistingSingletonHandles()` (`Mutex.OpenExisting(...).Close()`), persistent holding of `ROBLOX_singletonMutex`, `ROBLOX_singletonEvent`, and `Global\ROBLOX_singletonEvent`, plus the exclusive read lock on `%LocalAppData%\Roblox\LocalStorage\RobloxCookies.dat`.
2. **`RobloxHandleCloser` (`src/Infrastructure/Instance/RobloxHandleCloser.cs`)**:
   - Implemented Win32 P/Invoke handle enumeration (`NtQuerySystemInformation(SystemExtendedHandleInformation)`, `NtQueryObject`, `DuplicateHandle` with `DUPLICATE_CLOSE_SOURCE`) that runs every 3 seconds when `IsMultiInstanceEnabled` is true to close any `ROBLOX_singletonEvent` / `ROBLOX_singletonMutex` handles inside running `RobloxPlayerBeta.exe` processes.
3. **Tests (`tests/Infrastructure.Tests/Instance/NamedMutexInstanceGateTests.cs`)**:
   - Verified `CreateLenientMutex` and `RobloxHandleCloser.CloseMatchingHandlesInProcesses` closing live kernel event handles.
