# Milestone Report — M28.3: Win32 SetWindowPos Custom Resolution & Window Initialization Fix

## Summary
- Updated `User32.ResizeProcessMainWindowAsync` (`src/Infrastructure/Native/User32.cs`) to:
  1. Poll `while (process.MainWindowHandle == IntPtr.Zero && !process.HasExited)` every `200ms` with `process.Refresh()`.
  2. Wait an extra `1000ms` (`await Task.Delay(1000, ct)`) **after** `MainWindowHandle` becomes non-zero so the Roblox client finishes initializing its window before `SetWindowPos` is executed.
  3. Include `SWP_NOZORDER | SWP_NOMOVE | SWP_NOSENDCHANGING` (`0x0400`) so Windows does not clamp sub-800x600 dimensions via Roblox's `WM_GETMINMAXINFO` handler, and re-apply `SetWindowPos` once more after `1500ms` in case the client resets its window bounds during place load.
- Updated `AccountsViewModel` (`src/App.Wpf/ViewModels/AccountsViewModel.cs`) and `ServersViewModel` (`src/App.Wpf/ViewModels/ServersViewModel.cs`) to pass `CancellationToken.None` to the background post-launch tracking/resizing task (preventing `launchCts.Dispose()` / `joinCts.Dispose()` at the end of the queue from cancelling the background window poll) and pull `ResolutionWidth` / `ResolutionHeight` directly from `_settingsService.CurrentSettings`.
