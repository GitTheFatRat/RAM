# Milestone Report - M28.6: Resolve Resolution Snap-Back Using Roblox FastFlags

## Summary
- Added `RobloxFastFlagInjector` (`src/Infrastructure/Launch/RobloxFastFlagInjector.cs`):
  - `InjectResolutionFastFlags(robloxExePath, width, height)` creates `<version>\ClientSettings\ClientAppSettings.json` and merges `DFIntWindowSizeMinX` / `DFIntWindowSizeMinY`, preserving any existing flags (corrupt JSON is replaced).
  - `InjectIntoInstalledClients(width, height)` patches every `RobloxPlayerBeta.exe` found under `%LOCALAPPDATA%`, `Program Files`, and `Program Files (x86)` `Roblox\Versions`, because launches go through the `roblox-player:` protocol and the bootstrapper picks the version folder.
  - IO / access failures are logged as warnings and never block the launch.
- Called right before launch when `EnableCustomResolution` is on: `AccountsViewModel` (single + bulk launch) and `ServersViewModel` (join queue).
- Cleaned up `User32`: removed `WS_THICKFRAME` stripping, `GetWindowLongPtr` / `SetWindowLongPtr`, `SWP_FRAMECHANGED`, and `SWP_NOSENDCHANGING`. Kept a single initial `SetWindowPos(SWP_NOMOVE | SWP_NOZORDER)`, because the FastFlags only lower the minimum size and do not set the window's starting size.

## Caveats
- This machine's install is `C:\Program Files\Roblox\Versions\version-9ac8595712b447a7`. Writing there needs elevation, and the app manifest is `asInvoker`. Run the manager as Administrator, or the injection logs a warning and is skipped.
- Roblox restricts which client FastFlags it honors. If `DFIntWindowSizeMinX/Y` aren't on that list, the file gets written but the engine ignores it.
