# M21.6 Report — Verify & Fix: Registration Route Infinite Spin

## 1. Summary
- **Code Review (`IncognitoBrowserLauncher.cs` & `AddAccountViewModel.cs`)**:
  - Verified that both `OpenIncognitoBrowserCommand` and `OpenSignUpBrowserCommand` invoke `IncognitoBrowserLauncher.TryLaunch(url)`, which injects `--incognito --disable-quic --disable-features=EncryptedClientHello,Kyber,PostQuantumCECPQ2 "{url}"` (or `--inprivate` for Edge).
- **Live Network Diagnostics (Root Cause Analysis)**:
  - **Root Cause 1 (Roblox Envoy Edge Tarpit on `/` and `/login` for `loc=VN` IPs)**:
    - Live trace under Cloudflare WARP (`warp-cli mode warp+doh` + `warp-cli connect`) confirmed that Cloudflare WARP consumer mode assigns a Cloudflare egress IP (`104.28.251.202`, `AS13335 Cloudflare, Inc.`) whose GeoIP metadata preserves `"country": "VN"` (`loc=VN`).
    - When connecting to `www.roblox.com` (`128.116.97.3:443`, `server: public-gateway`), the TCP and TLS handshakes succeed, but `GET / HTTP/1.1` and `GET /login HTTP/1.1` are tarpitted by Roblox's edge proxy (`0 bytes received` until timeout, `HTTP 000`), causing the browser tab to spin indefinitely.
    - Conversely, `https://www.roblox.com/NewLogin` and `https://www.roblox.com/NewLogin?returnUrl=%2FCreateAccount` bypass the edge tarpit and return `HTTP 200 OK` (~71 KB) in `~0.5s`, and all `js.rbxcdn.com` bundles and `auth.roblox.com` endpoints return `HTTP 200 OK` in `~0.07s–0.45s`.
  - **Root Cause 2 (`DpiToolService.IsRunning()` False Positive When WARP GUI Tray Is Open)**:
    - When `Cloudflare WARP.exe` is running in the system tray while the WARP tunnel is `Disconnected`, `IsWarpTunnelConnected(warpCli)` returned `false`, and `DpiToolService.IsRunning()` previously fell through to `_processProvider.IsProcessRunning("Cloudflare WARP")`, returning `true` even though the tunnel was disconnected.
- **Fixes Implemented**:
  - Updated [`IncognitoBrowserLauncher.SignUpUrl`](../../src/App.Wpf/Services/IncognitoBrowserLauncher.cs) from the tarpitted `"https://www.roblox.com/"` to `"https://www.roblox.com/NewLogin?returnUrl=%2FCreateAccount"`.
  - Fixed [`DpiToolService.IsRunning()`](../../src/Infrastructure/Network/DpiToolService.cs) so that when `_useSystemInstallLookup` is active and `warp-cli.exe` is present, it returns `IsWarpTunnelConnected(warpCli)` directly without falling through to the tray GUI process check.
  - Updated [`DpiToolService.ConnectWarpCli()`](../../src/Infrastructure/Network/DpiToolService.cs) to enforce full tunnel + DoH (`--accept-tos mode warp+doh`) before connecting.
  - Expanded [`AddAccountViewModelTests.cs`](../../tests/App.Wpf.Tests/ViewModels/AddAccountViewModelTests.cs) and [`DpiToolServiceTests.cs`](../../tests/Infrastructure.Tests/Network/DpiToolServiceTests.cs) to verify both `LoginUrl` and `SignUpUrl` CLI flag generation and `warp+doh` orchestration.
