## Real bugs found & fixed
1. **Orphaned CDP Chrome + leaked `%TEMP%\RbxManager_Browser_*` profiles** (`IncognitoBrowserLauncher.cs`, `AddAccountWindow.xaml.cs`, `App.xaml.cs`)
   - Cookie polling kept running for up to 15 min after `.ROBLOSECURITY` was captured; Chrome was never killed.
   - Now: `Browser.close` after capture, WebSocket closed in `finally`, `Kill(entireProcessTree: true)` + `Dispose()` + retried profile deletion in `finally`. Active sessions tracked and killed on window close and app exit; stale profiles purged at startup.
2. **NullReferenceException when disposing mid-launch** (`AccountsViewModel.cs`)
   - `Dispose()` nulled `_bulkLaunchCts` while the queue was awaiting `LaunchAsync`; the loop then dereferenced the field. The queue now owns a local CTS; `Dispose()`/`CancelBulkLaunch()` only signal it. Regression test added.
3. **Orphaned 60–120s queues on navigation / app exit** (`App.xaml.cs`, `AccountsPage.xaml.cs`)
   - `AccountsViewModel`/`ServersViewModel` were transient, so navigating away left an invisible queue still launching. Now singletons; `OnExit` cancels both queues. Accounts page skips reload while a queue/check is running.
4. **Uncancellable server join queue** (`ServersViewModel.cs`)
   - `JoinWithAccountAsync` used `Task.Delay` with no token. Added `CancelJoin`, token-aware launch + delay, `IDisposable`.
5. **Cross-thread UI updates** (`AccountsViewModel.cs`)
   - Queue status properties and snackbars now go through `RunOnUiThread` (non-blocking `BeginInvoke` when off the UI thread, so a blocked UI thread can't deadlock).
6. **Event handler leak** — `AccountItemViewModel.PropertyChanged` handlers are unsubscribed on reload and dispose.
