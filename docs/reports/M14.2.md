# M14.2 Report: Robust Roblox Player Installation Check

**Target**: Post-M14 Hotfix  
**Date**: 2026-10-22  
**Status**: All Gates Passed

---

## 1. Scope & Implementation Summary

### Problem
- On Windows systems where Roblox was installed for all users or updated system-wide (e.g. to `C:\Program Files\Roblox`), the `roblox-player` protocol handler is registered in `HKEY_LOCAL_MACHINE` or `HKEY_CLASSES_ROOT`, but not `HKEY_CURRENT_USER`.
- Previously, `WindowsProcessStarter.IsRobloxPlayerInstalled()` and `WindowsRegistryProvider` only checked `HKEY_CURRENT_USER\Software\Classes\roblox-player\shell\open\command`, resulting in false negative reports that "Roblox Player is not installed on this system."

### Fix
- **`WindowsProcessStarter` (`IProcessStarter`)**:
  - Sequentially queries the three registry locations:
    1. `HKEY_CURRENT_USER\Software\Classes\roblox-player\shell\open\command`
    2. `HKEY_LOCAL_MACHINE\Software\Classes\roblox-player\shell\open\command`
    3. `HKEY_CLASSES_ROOT\roblox-player\shell\open\command`
  - Catches `SecurityException`, `UnauthorizedAccessException`, and other registry exceptions gracefully, continuing to the next hive.
  - Returns `true` if any location exists.
- **`WindowsRegistryProvider` (`IRegistryProvider`)**:
  - Updated `ProtocolHandlerExists(string protocol)` and `GetProtocolHandlerCommand(string protocol)` to check `HKCU`, `HKLM`, and `HKCR`.
  - Updated `StandardRobloxInstallFolderExists()` to check `%LOCALAPPDATA%\Roblox\Versions`, `%ProgramFiles%\Roblox\Versions`, and `%ProgramFiles(x86)%\Roblox\Versions`.
- **`WindowsProcessStarterTests`**:
  - Added unit tests verifying `IsRobloxPlayerInstalled()` executes without throwing and successfully detects Roblox when present in `HKLM` or `HKCR`.
