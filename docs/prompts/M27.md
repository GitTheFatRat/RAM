# M27 FEATURE: Active Instance Tracking & Kill Switch

## PROBLEM
Users need to see which specific accounts are currently running and have a dedicated button to kill (force close) the exact `RobloxPlayerBeta.exe` process associated with that account directly from the UI.

## TASKS

1. **Process ID Tracking on Launch:**
   - In the launch logic (e.g., `AccountsViewModel`, `JoinManager`, or CDP launcher), implement a mechanism to capture the new `RobloxPlayerBeta` Process ID.
   - *Recommended approach:* Take a snapshot of `Process.GetProcessesByName("RobloxPlayerBeta").Select(p => p.Id)` immediately before triggering the launch URI, wait for the process to spawn, take another snapshot, and identify the new PID.
   - Assign this PID to a new property on the account model: `public int? ActiveProcessId { get; set; }`.

2. **ViewModel Updates:**
   - Add a bindable property `public bool IsRunning => ActiveProcessId.HasValue;` (ensure `INotifyPropertyChanged` is triggered when `ActiveProcessId` changes).
   - Create an `ICommand KillInstanceCommand` that executes: `Process.GetProcessById(ActiveProcessId.Value).Kill();`, gracefully catches exceptions (if the process already exited manually), and resets `ActiveProcessId = null`.
   - Implement a lightweight background watcher or use `Process.EnableRaisingEvents` on the captured process to automatically set `ActiveProcessId = null` if the game window is closed by the user or crashes.

3. **UI Integration:**
   - In `AccountsPage.xaml` (and `ServersPage.xaml` if applicable), add a "Kill" (Tắt) button or a red icon to the DataGrid row/list template.
   - Bind the button's `Visibility` to `IsRunning` (using a BooleanToVisibilityConverter).
   - Bind the button's `Command` to `KillInstanceCommand`.
   - Add a UI indicator (e.g., "Đang chạy" text or a green dot) bound to `IsRunning`.
