# M28.1 BUG FIX: Custom Resolution Settings Persistence

## PROBLEM
The user changes the custom resolution (e.g., to 200x400) in the Settings tab, but upon navigating to another tab and coming back, it resets to the default 800x600. The values are not being persistently saved to the settings configuration or reloaded upon ViewModel initialization.

## TASKS

1. **Update SettingsViewModel.cs:**
   - Locate the `ResolutionWidth` and `ResolutionHeight` properties (and `EnableCustomResolution` toggle).
   - In the constructor (or initialization method), ensure these properties are populated directly from `ISettingsService.CurrentSettings` (or the equivalent settings provider), rather than hardcoded default values.
   - In their `set` accessors, ensure that when the value changes, it updates the underlying `ISettingsService.CurrentSettings` object and triggers the `Save()` method (or equivalent) to write the changes to `settings.json`.

2. **Update SettingsPage.xaml bindings:**
   - Ensure the `TextBox` bindings for Width and Height have `Mode=TwoWay` and `UpdateSourceTrigger=PropertyChanged` (or `LostFocus`) so the ViewModel captures the input immediately as the user types or leaves the textbox.

## FINISH
Run `dotnet build` to ensure no errors.
Commit message: "fix: make custom resolution settings persistent across navigation".
