# M32 FEATURE: Auto-Tile Windows & Disconnection Recovery

## PROBLEM
1. Multiple custom-sized windows (e.g., 200x400) launch in the center of the screen and overlap, requiring manual drag-and-drop.
2. Network instability (Packet loss, Disconnection/Error 277) causes Roblox to freeze or show a disconnect modal without exiting the process. Standard process trackers fail to detect this, halting AFK farming.

## TASKS

1. **Auto-Tile Windows (Grid Layout):**
   - Add a UI toggle in Settings: "Tự động xếp cửa sổ (Auto-Tile)".
   - Implement a layout manager in `WindowResizer` or `WindowSizeLock`. 
   - Calculate available screen bounds (`SystemParameters.WorkArea`). Based on the saved custom Width/Height, calculate a grid (X, Y coordinates).
   - When a new instance is verified, assign it the next available grid slot and apply the coordinates via `SetWindowPos` (dropping the `SWP_NOMOVE` flag for the initial placement).

2. **Disconnection & Packet Loss Recovery (Auto-Relaunch):**
   - Add a UI toggle in Settings: "Tự động kết nối lại khi rớt mạng (Auto-Reconnect)".
   - Build an `InstanceWatchdogService` that polls running account processes every 15 seconds.
   - **Detection Logic:**
     - Check `process.HasExited` (Crash detection).
     - Check `!process.Responding` (Packet loss / Engine hang detection).
     - *Log Polling (Crucial):* Identify the specific log file in `%localappdata%\Roblox\logs` locked by the PID. Tail the last few lines for disconnection signatures (e.g., "Error 277", "Connection lost", "Disconnect", "Timeout").
   - **Recovery Logic:** 
     - If a disconnect or hang is detected, execute `process.Kill()`.
     - Trigger a 20-second cooldown, then automatically re-invoke the launch sequence (using the account's credentials and last intended PlaceId/JobId).
