# M25.3 FEATURE Global Exception Handler & Crash Logger

## PROBLEM
The published WPF application might encounter hidden runtime errors (e.g., missing dependencies, single-file extraction issues, or reflection failures) that cause silent crashes or generic error dialogs. We need a global logging mechanism to capture ALL unhandled exceptions and write them to a log file for easy debugging.

## TASKS
1. Implement Global Handlers in `App.xaml.cs`
   - Override the `OnStartup` method (or add to the constructor) to register the following global error handlers
     a. `Application.Current.DispatcherUnhandledException` (Catches UI thread exceptions).
     b. `AppDomain.CurrentDomain.UnhandledException` (Catches background thread exceptions).
     c. `TaskScheduler.UnobservedTaskException` (Catches unawaited async task exceptions).

2. Create the Logging Logic
   - In each handler, extract the `Exception` object (Message, StackTrace, and InnerException).
   - Write these details explicitly to a file named `crash_log.txt` located in `AppDomain.CurrentDomain.BaseDirectory`.
   - Ensure the UI thread handler marks `e.Handled = true` if possible, or shows a simple MessageBox explicitly stating A fatal error occurred. Check crash_log.txt for details. before shutting down gracefully.

## FINISH
Run `dotnet build` to ensure no syntax errors.
Commit message feat add global exception handlers and crash_log.txt generation.
