# M7: diagnostics, editable launch templates, code health

Follow docs/prompts/RUNBOOK.md (rules, gates, token budget, security, autonomy). First add M7 to docs/STATE.md as pending. Batch file writes; do not narrate.

## WHY
The three core Roblox paths (cookie validation, auth ticket, launch URI) are UNVERIFIED against a live client, and Roblox changes them often. The Tech Lead cannot see the user's machine. This milestone lets the user (a) see exactly which step fails in a redacted report that is safe to paste, and (b) fix a changed URI format by editing a JSON setting instead of waiting for a rebuild.

## SCOPE
In: launch URI templates, dry run, Diagnostics page with redacted report, code health pass.
Out: any new Roblox feature (see M9).

## 1. EDITABLE LAUNCH TEMPLATES
1. AppSettings gets an Advanced section: string? LaunchUriTemplate, string? PlaceLauncherUrlTemplate. Null means the built-in default.
2. Express the current built-in formats as templates. Allowed placeholders only: {ticket}, {launchTimeMs}, {placeLauncherUrl} (already URL-encoded), {trackerId}, {request}, {placeId}, {gameIdParam} (expands to "&gameId=<jobId>" or empty).
3. Validation (pure function, unit tested):
   - LaunchUriTemplate must start with "roblox-player:" and contain {ticket}.
   - PlaceLauncherUrlTemplate must be https, its host must be roblox.com or end with ".roblox.com", and it must contain {placeId}.
   - Unknown placeholders make the template invalid.
   - An invalid override is ignored: use the default, log a warning (operation name only), and show the problem in Diagnostics.
4. The URI builder uses the effective templates. The ticket is never logged and never stored.
5. Settings page: read-only "Advanced" expander showing whether overrides are active and whether they are valid. No editing UI; editing is by settings.json only. Document the keys and an example in README.vi.md.

## 2. DRY RUN
In the Launch dialog add "Dry run": builds the URI with the literal text <ticket> instead of a real ticket, makes NO network call and does NOT start any process, and shows the resulting structure. Reuse the same builder.

## 3. DIAGNOSTICS PAGE
Navigation item "Chan doan" (use proper Vietnamese diacritics in Strings.vi.resx). Buttons: "Run diagnostics" and "Copy report". Read-only text area for the report. Sections:
1. Environment: app version, OS version and build, .NET runtime version, process architecture, whether the app runs elevated (warn if yes), UI culture, WebView2 runtime version or "missing".
2. Roblox client: whether the roblox-player protocol handler exists in HKCU\Software\Classes, the handler command path (flag if it contains "Bloxstrap" or "Fishstrap", since bootstrappers change behavior), whether the standard Roblox install folder exists, running RobloxPlayerBeta count, multi-instance gate state (available, enabled).
3. Network (no cookie sent): status code only (or the exception type) for GET https://www.roblox.com/ and one public GET on each of users, auth, games, presence and apis hosts (roblox.com subdomains), system proxy in use yes or no, and elapsed milliseconds.
4. Templates: whether overrides are active and valid.
5. Optional per-account check (account picker, one account at a time): validate result code; CSRF token obtained yes or no; ticket obtained yes or no (boolean only); the launch URI rendered with <ticket> as in dry run; for any non-success response only the HTTP status, the Roblox JSON errors[].code integers, and each errors[].message truncated to 120 characters.
6. Output rules: English keys, plain text, no cookie, no ticket, no header VALUES (header names only), no response bodies beyond what is listed. Pass the whole report through the existing redaction filter before display and before copying.
7. "Copy report" puts the text on the clipboard and shows a snackbar. Add one line at the top of the report: "Safe to share: redacted. No cookies or tickets."

## 4. CODE HEALTH
1. Run dotnet format once and commit the result. Add a CI step "dotnet format --verify-no-changes".
2. Audit and fix: no async void except event handlers; every public async method that does I/O accepts a CancellationToken; no .Result or .Wait() on the UI thread; no new HttpClient() outside the factory; every Process object is disposed; every IDisposable SecretValue is disposed.
3. List the findings and fixes in the report in at most 15 lines.

## TESTS
- Template validation: each valid and invalid case, unknown placeholders, non-roblox host, http scheme, missing {ticket} or {placeId}.
- Regression: default templates produce exactly the same URI string as the pre-M7 builder for the same inputs (compare against fixtures built from the old logic).
- Override applied; invalid override falls back to default.
- Dry run: no HTTP call and no process start (fakes assert zero invocations).
- Diagnostics: use fakes for registry, process provider, HTTP and clock. With a fake cookie "FAKE_COOKIE_FOR_TESTS_123", fake ticket "FAKE_TICKET_FOR_TESTS_456" and a fake response body containing both strings, assert the final report contains neither. Assert header values never appear. Assert the report starts with the "Safe to share" line.
- Log-leak and ArchitectureTests still pass; the Reveal() allowlist must NOT grow in this milestone.
