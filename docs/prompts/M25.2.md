# M25.2 BUG FIX: WPF BAML/TypeConverter Crash on Published Build

## PROBLEM
The published `RbxManager.App.exe` crashes immediately on startup with the error: 
"Provide value on 'System.Windows.Baml2006.TypeConverterMarkupExtension' threw an exception."
This is a known WPF issue when using aggressive AOT/Publish settings like `PublishTrimmed`, `PublishReadyToRun`, or `PublishSingleFile` without extracting resources. The XAML parser fails to resolve type converters via reflection because the metadata is stripped or packed incorrectly.

## TASKS
1. **Clean up `.csproj`:** Inspect `src/App.Wpf/App.Wpf.csproj`. Remove any `<PublishTrimmed>` or `<PublishReadyToRun>` tags if they were hardcoded in the property groups.
2. **Execute Safe WPF Publish Command:** Run the following `dotnet publish` command. It forces Trimming and ReadyToRun to be OFF, and enables `IncludeAllContentForSelfExtract` which is strictly required for WPF Single-File applications to parse BAML correctly.
   
   Execute this command in the terminal:
   `dotnet publish src/App.Wpf/App.Wpf.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeAllContentForSelfExtract=true -p:PublishTrimmed=false -p:PublishReadyToRun=false -o "$env:USERPROFILE\Desktop\RbxManager_ProtectedBuild"`

3. **Fallback (If it still crashes):** If the WPF SingleFile compilation fundamentally breaks a specific 3rd-party UI library you are using, re-run the publish command without `-p:PublishSingleFile=true` to output a standard multi-file self-contained folder instead.

## FINISH
Run the safe publish command and output the binaries to `RbxManager_ProtectedBuild`.
Commit message: "fix: resolve WPF Baml2006 crash by disabling trimming/r2r and enabling full content extraction".
