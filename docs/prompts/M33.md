# M33 FEATURE: Per-Instance Proxy (API & Auth Routing)

## PROBLEM
Launching 15-20 accounts from the same local IP triggers Roblox's anti-bot systems, resulting in Error 268 (Unexpected Client Behavior), CAPTCHA flags, or IP-based rate limits (429/403) during the login and ticket-fetching phases.

## TASKS

1. **Proxy Configuration per Account:**
   - Update the local `vault.dat` schema (Account Model) to include an optional `Proxy` string field. Support standard residential proxy formats (e.g., `IP:Port:Username:Password` or `Host:Port`).
   - Add a UI input field in the Account creation/edit dialog to configure and save this proxy.

2. **Network Layer Integration (`RobloxHttpClientFactory`):**
   - Modify the `HttpClient` generation logic. If an account has a configured proxy, inject a `WebProxy` with the parsed credentials into the `HttpClientHandler`.
   - Ensure all background API calls for that specific account (CSRF fetching, Auth Tickets, Presence polling for Follow Player) are strictly routed through its assigned proxy.

3. **Live Data Verification & Audit:**
   - Create a live verification task that tests a proxy connection (if a test proxy is provided) by hitting a Roblox API endpoint (e.g., `users.roblox.com/v1/users/authenticated`).
   - Output the results into a new `docs/reports/M33_Audit_Report.md` file, confirming whether the proxy successfully masked the IP and handled the authentication request without triggering rate limits.
