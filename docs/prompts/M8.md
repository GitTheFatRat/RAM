# M8: UI/UX polish (modern, clean, high density)

Follow docs/prompts/RUNBOOK.md (rules, gates, token budget, security, autonomy). First add M8 to docs/STATE.md as pending. Batch file writes; do not narrate. No new Roblox behavior, no new Reveal() callers.

## DESIGN DIRECTION
Modern, minimal, productivity-oriented Windows app (Fluent via WPF-UI), compact spacing for power users, borders over shadows, vivid color reserved for status. Dark default, Light must also be fully correct.

## 1. DESIGN TOKENS
1. One ResourceDictionary (for example Themes/Tokens.xaml) defines every custom color, brush, corner radius, spacing and font size used by the app. Spacing on an 8 px grid (4 for tight). No hard-coded hex colors or magic numbers in page XAML.
2. Status colors as tokens with Dark and Light variants: Valid, Expired, Error, Unknown, Running. Every status is shown as chip with BOTH an icon or glyph and text, never color alone. Text on chips meets contrast 4.5:1 in both themes.
3. Typography: Segoe UI Variable via the WPF-UI defaults; a type scale of 12 / 14 / 16 / 20 / 28 for caption, body, subtitle, title, display. Monospace (Cascadia Mono, fallback Consolas) for ids, PIDs, server ids and the diagnostics report.

## 2. ACCOUNTS PAGE
1. DataGrid: sortable columns (Alias, Group, Username, Status, Last checked, Created), a checkbox selection column, virtualization on (smooth with 300+ rows), row height compact, subtle hover and selected states, no heavy gridlines.
2. Last checked shows localized relative time ("5 phút trước", "5 minutes ago"); full timestamp in a tooltip. A pure formatter with tests.
3. Search with 200 ms debounce; group chips remain. Persist the sort column and direction.
4. Toolbar: primary actions "Launch" (accent button) and "Add" (split button: via login, via cookie). Secondary actions (Check, Check all, Edit, Delete, Backup, Rename group) in a "More" menu. Disable actions that do not apply to the current selection.
5. Row context menu (right click): Launch, Check, Edit, Delete, Copy alias. There is NO copy-cookie action anywhere.
6. Empty state: icon, one-line explanation, and two buttons (Add via login, Add via cookie). A different empty state for "no search results" with a "Clear search" button.
7. Busy states: while checking, show an inline progress indicator and disable the triggering button; keep the UI responsive.

## 3. OTHER PAGES
1. Running page and Servers page: same density, tokens, monospace ids, empty states with a short hint, loading indicator while fetching, retry button on error.
2. Settings page: grouped into cards with a secondary descriptive subtitle each (Appearance, Launching, Auto-rejoin, Multi-instance, Backup, Advanced). Show the multi-instance risk text next to its toggle.
3. Snackbars: queue rather than overwrite; success auto-dismisses, errors stay until dismissed.

## 4. WINDOW AND SHELL
1. Persist window size, position, maximized state, last selected page and per-page column widths in a UiState section of settings.json. On restore, validate against current screen bounds; if off-screen, reset to centered default. Minimum size 960 x 600.
2. Keyboard: every action reachable with the keyboard, logical tab order, visible focus rectangle. Keep the existing shortcuts and add Ctrl+N (add via login), F5 (refresh current page), Esc closes dialogs.
3. AutomationProperties.Name on every icon-only button.
4. High DPI: no blurry bitmaps; use vector icons only.
5. Optional (skip if it takes more than a small one-off script): generate a simple monogram app icon (rounded square, letter "R") with a throwaway script, commit the .ico, set it as the application icon. Never ship the script.

## 5. LOCALIZATION AUDIT
1. Audit Strings.vi.resx: every Vietnamese string must use full diacritics (for example "Tài khoản", "Cài đặt", "Chẩn đoán", "Đang chạy", "Máy chủ"). Fix any ASCII-only Vietnamese found, including navigation labels and dialog texts from earlier milestones.
2. No value in Strings.vi.resx may equal its English counterpart except an allowlist of product and technical terms (RbxManager, FPS, Ping, PID, WebView2, JSON).
3. Dates, relative times and numbers use the active culture.
