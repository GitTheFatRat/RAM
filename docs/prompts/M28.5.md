# M28.5 BUG FIX: Window Snapping Back or Resizing on Drag

## PROBLEM
The custom resolution works initially, but when the user drags the Roblox window, it snaps back to its original position or resizes back to the default minimum. This happens because Roblox's internal engine reacts to Windows drag events and enforces minimum bounds, OR the tool has a background loop aggressively enforcing coordinates.

## TASKS
1. **Stop Aggressive Position Polling:** Ensure `SetWindowPos` is only called ONCE after the window is fully initialized, NOT in a continuous background loop that forces X/Y coordinates.
2. **Strip Sizing Borders (Crucial):** Before calling `SetWindowPos`, you MUST strip the `WS_THICKFRAME` (0x00040000) style from the window using Win32 `GetWindowLongPtr` and `SetWindowLongPtr`. Without the sizing border, Roblox's internal size-correction logic will not trigger when the window is dragged.
3. **Preserve Position:** When calling `SetWindowPos`, you must pass the `SWP_NOMOVE` (0x0002) and `SWP_NOZORDER` (0x0004) flags so the API only modifies the size (cx, cy) and allows the user to freely drag the window anywhere.

## FINISH
Run `dotnet build`.
Commit message: "fix: strip WS_THICKFRAME and use SWP_NOMOVE to prevent window snap-back on drag".
