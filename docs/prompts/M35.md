# M35 FEATURE: Window Focus & Minimize Bug Fix

## PROBLEM
When multiple Roblox instances are tiled, clicking on one instance causes the other to minimize automatically. This is due to Roblox retaining exclusive fullscreen flags or the Win32 placement missing non-activation flags, triggering Windows' default focus-loss minimization.

## TASKS

1. **Strip Window Styles (Force Windowed Mode):**
   - In `RobloxWindowSizer` and `WindowSizeLock`, before applying `SetWindowPos`, read the current window style using `GetWindowLong(hWnd, GWL_STYLE)`.
   - Remove fullscreen/maximize flags and force a standard window with borders (or strict borderless without exclusive fullscreen).
   - E.g., `style &= ~(WS_MAXIMIZEBOX | WS_MINIMIZEBOX);`

2. **Update `SetWindowPos` Flags:**
   - Modify the `User32.MoveResizeWindow` implementation or its callers to explicitly include:
     - `SWP_NOACTIVATE` (0x0010): Does not activate the window.
     - `SWP_NOZORDER` (0x0004): Retains the current Z order (ignore the `hWndInsertAfter` parameter).
   - This ensures that when the background worker re-applies the size lock or grid position, it does not steal focus or mess with the active window's Z-order.

3. **Prevent Auto-Minimize via `ShowWindow`:**
   - If the window is detected as minimized (`IsIconic(hWnd)` is true), force it back to normal using `ShowWindow(hWnd, SW_RESTORE)` before attempting to tile it.

## FINISH
Run `dotnet build`.
