# M32.1 FEATURE: Auto-Tile Windows, Disconnection Recovery & Real Data Audit

## PROBLEM
1. Multiple custom-sized windows (e.g., 200x400) launch in the center of the screen and overlap, requiring manual drag-and-drop.
2. Network instability (Packet loss, Disconnection/Error 277) causes Roblox to freeze or show a disconnect modal without exiting the process. Standard process trackers fail to detect this, halting AFK farming.
3. We need 100% verified confidence that the Win32 window positioning and the log-parsing watchdog work on a real Windows environment before merging.

## TASKS

1. **Auto-Tile Windows (Grid Layout):**
   - Add a UI toggle in Settings: "Tự động xếp cửa sổ (Auto-Tile)".
   - Implement a layout manager to calculate available screen bounds (`SystemParameters.WorkArea`). 
   - Based on the saved custom Width/Height, calculate a grid (X, Y coordinates).
   - When a new instance is verified, assign it the next available grid slot and apply the coordinates via `SetWindowPos` (drop the `SWP_NOMOVE` flag for the initial placement).

2. **Disconnection & Packet Loss Recovery (Auto-Relaunch):**
   - Add a UI toggle in Settings: "Tự động kết nối lại (Auto-Reconnect)".
   - Build an `InstanceWatchdogService` that polls running account processes every 15-30 seconds.
   - **Detection Logic:**
     - Check `process.HasExited` (Crash detection).
     - Check `!process.Responding` (Packet loss / Engine hang detection).
     - *Log Polling (Crucial):* Identify the specific log file in `%localappdata%\Roblox\logs` locked by the PID. Tail the last few lines for disconnection signatures (e.g., "Error 277", "Connection lost", "Disconnect").
   - **Recovery Logic:** If a disconnect/hang is detected, execute `process.Kill()`, wait for a 20s cooldown, then automatically re-invoke the launch sequence.

3. **Real Data & Environment Verification (Audit):**
   - **Tile Verification:** Write a test that launches 2 dummy processes (e.g., Notepad) or real Roblox instances and verifies that the X/Y coordinates outputted by the Grid calculation do not overlap.
   - **Log Parsing Verification:** Point the log reader at a real historical Roblox log file (or create a realistic mock log with disconnect strings) and assert that the Watchdog successfully triggers the recovery flag.
   - **Generate Factual Report:** Create `docs/reports/M32_Audit_Report.md` documenting the exact, real-world outcomes of the Grid positioning and Log reading tests.
