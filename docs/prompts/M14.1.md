# M14.1 HOTFIX: Fix Binding Error on ConverterParameter

Follow docs/prompts/RUNBOOK.md (rules, gates, token budget). Batch file writes.

## PROBLEM
When the user clicks on the "Servers" (Máy chủ) navigation tab, the application crashes with the following `XamlParseException`:
"A 'Binding' cannot be set on the 'ConverterParameter' property of type 'Binding'. A 'Binding' can only be set on a DependencyProperty of a DependencyObject."

This happens because a `Binding` expression is illegally being assigned to the `ConverterParameter` of another `Binding` inside the XAML code, most likely in `ServersPage.xaml` or its child controls.

## TASKS
1. Carefully audit `src/App.Wpf/Views/Pages/ServersPage.xaml` and any associated controls or resources (like `DataGrid` columns, row styles, or buttons within the servers page).
2. Locate any `Binding` that attempts to set `ConverterParameter={Binding ...}`.
3. Fix the issue. You cannot use a `Binding` for `ConverterParameter`.
   - **Alternative 1:** If multiple values need to be evaluated together, change the single `Binding` with a Converter to a `MultiBinding` and use an `IMultiValueConverter`. The values you wanted to pass via `ConverterParameter` should instead be passed as additional `<Binding>` elements inside the `<MultiBinding>`.
   - **Alternative 2:** If the parameter is actually static, replace `{Binding ...}` with a static value or a `StaticResource`.
4. Ensure the UI still functions as intended (e.g., sorting, formatting player counts, or executing commands with the correct context).
