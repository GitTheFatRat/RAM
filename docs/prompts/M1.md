## CORE (src/Core, no WPF or Infrastructure dependency)
1. SecretValue (sealed class, IDisposable): wraps a byte[] (UTF-8 of the secret).
   - Factory SecretValue.FromString(string). Method string Reveal() is the ONLY way to read it.
   - Dispose zeroes the array (CryptographicOperations.ZeroMemory).
   - ToString() returns "[REDACTED]". Equals/GetHashCode must not expose content.
2. Account (sealed record or class): AccountId Id, string Alias, string? Group, string? Note, SecretValue Cookie, DateTimeOffset CreatedAt, string? Username (null until M2).
   Validation in Core, returned as a result type (do not throw for user input):
   - Alias: required, trimmed, 1-50 chars, unique case-insensitive across accounts.
   - Group <= 30 chars. Note <= 200 chars.
   - Cookie non-empty after trim. No format check on the cookie.
3. IAccountStore: Task<IReadOnlyList<Account>> ListAsync(); Task<Result> AddAsync(Account); Task<Result> UpdateAsync(Account); Task RemoveAsync(AccountId).
   Define a minimal Result type only if one does not already exist.

## INFRASTRUCTURE (src/Infrastructure)
4. EncryptedFileVault : IAccountStore.
   - Path: %LOCALAPPDATA%\RbxManager\vault.dat (path injectable via constructor for tests).
   - Serialize with an INTERNAL DTO (System.Text.Json). Core Account is never serialized directly.
   - File format v1 (binary): magic "RBXV" (4 bytes) | version byte = 1 | wrappedKeyLength (UInt16 LE) | wrappedKey | nonce (12 bytes) | tag (16 bytes) | ciphertext.
   - Every save: NEW random 32-byte data key and NEW random 12-byte nonce. Encrypt with AES-GCM. AAD = magic + version bytes. Wrap the data key with ProtectedData.Protect(DataProtectionScope.CurrentUser). Zero data key and plaintext buffers after use.
   - AesGcm: use the constructor that takes an explicit tag size (16). The parameterless constructor is obsolete and TreatWarningsAsErrors will fail the build.
   - Add System.Security.Cryptography.ProtectedData via central package management. Verify compatibility with net10.0-windows and report the version.
   - Atomic write: write vault.dat.tmp, then File.Replace(tmp, vault.dat, vault.dat.bak). First save (no existing file): File.Move.
   - Load: file missing -> empty list. Wrong magic/version, tag failure, or DPAPI failure -> throw VaultCorruptedException (typed, message WITHOUT any secret). NEVER silently create an empty vault over an unreadable one.
   - Concurrency: SemaphoreSlim around all operations. Load-modify-save per operation (KISS, no cache).
   - Logging via ILogger: operation names and counts only. NEVER log cookie, plaintext, or keys.

## APP.WPF
5. Accounts page (replace the placeholder). MVVM with CommunityToolkit.Mvvm. All text from Strings.resx / Strings.vi.resx (vi default).
   - Search box filters by alias, group, note (case-insensitive).
   - ui:DataGrid or ListView with columns Alias, Group, Created. The cookie is NEVER displayed and there is NO copy-cookie feature.
   - Buttons Add, Edit, Delete. Delete asks for confirmation in a ui:ContentDialog. Show an empty-state text when there are no accounts.
   - Add/Edit in a ui:ContentDialog: Alias, Group, Note, Cookie via PasswordBox (NOT a bound string property). On save, read the PasswordBox once, build a SecretValue, then clear the PasswordBox.
   - On Edit the cookie field starts empty and means "keep the existing cookie" unless the user types a new one.
   - Show Core validation messages inline in the dialog (localized). Snackbar on success or failure.
   - On VaultCorruptedException show an error dialog with the vault path and a message that the file was NOT overwritten. Do not crash.
6. Register EncryptedFileVault as IAccountStore in DI.

## TESTS (tests/Core.Tests and a new tests/Infrastructure.Tests, add to the solution)
- SecretValue: ToString is redacted; Dispose zeroes memory; Reveal round trip.
- Account validation: every rule, including case-insensitive duplicate alias.
- Vault (use a temp directory):
  - add -> a new vault instance loads the same data; update; remove.
  - ciphertext on disk does not contain the alias or cookie plaintext bytes.
  - flipping one ciphertext byte -> VaultCorruptedException.
  - flipping one tag byte -> VaultCorruptedException.
  - wrong magic -> VaultCorruptedException.
  - saving identical data twice produces different file bytes (fresh key and nonce).
  - .bak is created on the second save.
- No test may use a real Roblox cookie. Use fake strings such as "FAKE_COOKIE_FOR_TESTS_123".
