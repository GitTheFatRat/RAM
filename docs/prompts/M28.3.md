# M28.3 BUG FIX: Win32 SetWindowPos Ignoring Saved Custom Resolution

## PROBLEM
The custom resolution is correctly saving to settings.json (e.g., 200x400), but when Roblox launches, the window still resizes to 800x600 or stays at default. The launch logic is either hardcoding the resolution values or attempting to resize the window before it is fully initialized by the OS.

## TASKS

1. **Remove Hardcoded Values:**
   - Locate the launch logic where `SetWindowPos` is called (e.g., in `AccountsViewModel`, `JoinManager`, or the launch service).
   - Ensure the width and height parameters are pulled directly from the current settings instance (e.g., `_settingsService.CurrentSettings.ResolutionWidth`). 
   - Remove any fallback or hardcoded `800` and `600` values passed to the Win32 API.

2. **Robust Window Handle Polling & Delay:**
   - Modifying window bounds immediately upon process creation often fails because the window isn't fully rendered.
   - Implement a polling loop:
     ```csharp
     while (process.MainWindowHandle == IntPtr.Zero && !process.HasExited)
     {
         await Task.Delay(200);
         process.Refresh();
     }
     ```
   - **CRITICAL:** Add an extra `await Task.Delay(1000);` (1 second) *AFTER* `MainWindowHandle` is found, to give the Roblox client time to fully draw its window before executing `SetWindowPos`.

3. **Verify Execution:**
   - Wrap the `SetWindowPos` call in a try/catch and log success/failure.
   - Ensure the flags include `SWP_NOZORDER | SWP_NOMOVE` (unless you also want to stack them neatly, in which case handle X/Y).

## FINISH
Run `dotnet build`.
