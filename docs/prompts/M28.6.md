# M28.6 DEFINITIVE FIX: Roblox Window Snap-back on Drag (FFlag Override)

## 1. INVESTIGATION & ROOT CAUSE ANALYSIS
- **Symptom:** Win32 `SetWindowPos` works initially, but dragging the window causes it to snap back to default size (e.g., 800x600).
- **Cause:** When a user drags a window, Windows sends the `WM_GETMINMAXINFO` message. The internal Roblox engine processes this, reads its hardcoded minimum window bounds, and forces a resize. External Win32 API calls cannot permanently override this without DLL hooking (which risks Hyperion anti-cheat bans).
- **Definitive Solution:** Abandon the aggressive Win32 forced-resize loop. Instead, utilize Roblox's internal configuration system (**FastFlags**). By creating a `ClientAppSettings.json` file in the Roblox version folder before launch, we can natively rewrite Roblox's internal minimum size limits (`DFIntWindowSizeMinX` and `DFIntWindowSizeMinY`).

## 2. TASKS

**Step 1: Clean Up Old Logic**
- Remove the aggressive Win32 `SetWindowPos` loop that forces custom resolution from the previous `M28` implementations. We no longer need to fight the OS.

**Step 2: Implement FFlag Injector**
- In the launch sequence (right before starting `RobloxPlayerBeta.exe`), write a method: `InjectResolutionFastFlags(string robloxExePath, int width, int height)`.
- **Logic:**
  1. Determine the directory of the target `RobloxPlayerBeta.exe`.
  2. Create a folder named `ClientSettings` inside that directory (if it doesn't exist).
  3. Inside `ClientSettings`, create/modify a file named `ClientAppSettings.json`.
  4. Merge or write the following JSON structure:
     ```json
     {
       "DFIntWindowSizeMinX": <width>,
       "DFIntWindowSizeMinY": <height>
     }
     ```
  5. Ensure this is executed right before `Process.Start()`.

**Step 3: Execution & Verification**
- If `EnableCustomResolution` is true, inject the user's saved Width/Height into the FFlag JSON.
- Let Roblox launch normally. Because the engine itself now believes the minimum size is 200x400, the user can freely drag, move, or resize the window natively without any snap-backs.
