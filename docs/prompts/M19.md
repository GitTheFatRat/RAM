# M19: UAT Telemetry (Live Desktop Debugging)

Follow docs/prompts/RUNBOOK.md. Batch file writes.

## PROBLEM
The end-user needs 100% transparent proof of what the application is doing under the hood during manual UAT (User Acceptance Testing) to ensure no hidden processes, fake reports, or unexpected API calls occur.

## TASKS
1. **UAT Mode Toggle**:
   - Add `bool EnableUatTelemetry` to `AppSettings` (default: false). Add a toggle in the Advanced section of `SettingsPage.xaml` (localized: "Bật chế độ ghi log thực chiến ra Desktop").
2. **Telemetry Output**:
   - Create a specialized `UatLogger` that bypasses normal rolling logs. 
   - When `EnableUatTelemetry` is true, it writes raw, unencrypted execution traces to `Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.Desktop), "RbxManager_UAT_Trace.txt")`.
3. **Crucial Interception Points**:
   - Log the EXACT command line arguments used when calling `Process.Start` in `WindowsProcessStarter`. (Ensure cookie/ticket is masked with `***` to maintain security, but show the full URI structure).
   - Log the exact P/Invoke signals sent by `WindowController` and `WindowsMemoryOptimizer` (e.g., "Calling SetProcessWorkingSetSize(-1, -1) on PID 1234").
   - Log every state transition in `SessionTracker` (e.g., "Session 1234 bound to JobId XYZ", "LogWatcher triggered Error 277 on PID 1234").
4. **Hygiene**:
   - Only log to the Desktop file if the setting is explicitly enabled. Keep the file stream open or append safely.

## FINISH
Run `dotnet build -c Release`. 
Commit "feat: M19 UAT telemetry for absolute transparency during manual testing".
